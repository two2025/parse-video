# 解析与下载的出站边界

旧 API 保留路径和响应格式，Web UI、v1、旧 API、CLI 和库入口共享解析器的 URL 校验。每个平台分别声明分享入口与允许访问的上游主机，统一传输层校验所有请求，包括自动重定向与解析器从 `Location` 或上游内容取出地址后发起的请求。把这条边界放在解析器的请求链路，可以保留接口兼容性并覆盖 HTTP handler 之外的调用。

延续 [ADR 0001](0001-proxy-support.md) 的显式 HTTP/HTTPS 代理配置。直连时，应用解析并校验目标 IP，随后拨号到通过校验的地址。出站传输只使用显式配置的 `PARSE_VIDEO_PROXY`。启用代理时，应用继续校验目的主机，由受信任代理限制实际目标 IP。代理故障直接返回错误，避免绕过出站限制。

## 实施顺序与验收

1. **封堵 SSRF。** 用解析后的主机名选择平台，按 DNS 标签边界匹配，并拒绝 URL 用户信息、不支持的协议及未明确允许的端口。逐个平台补齐合法跳转、API 与媒体探测主机；对所有跳转设置次数上限。禁止拨号到私网、回环、链路本地、共享地址空间和其他特殊用途网段，校验前归一化 IPv4 映射 IPv6。直连以已校验 IP 建连，同时保留原主机名用于 TLS 验证。代理模式要求部署者验证代理的私网拦截，代理失败时保持失败。跨主机跳转清理敏感请求头。

   用本机模拟服务验证路径伪装域名、主机后缀冒充、自动与手动跳转、IPv4/IPv6 回环、DNS 重绑定及代理失效。对正常短链、作品页和平台切换跳转做回归，保留旧 API 的响应外形和 v1 的错误分类。

2. **封堵 Web XSS。** 以 DOM API 构建解析结果及错误提示，标题和错误使用纯文本。视频、音频、封面、图集及 LivePhoto 链接只接受经 URL 解析确认的 HTTP/HTTPS 地址。浏览器回归验证恶意标题、属性注入、`javascript:`、`data:` 和错误消息，检查合法预览和下载功能。为固定版本的 CDN 脚本和样式添加完整性校验。

3. **限制资源用量与保护配置。** 为 HTTP 服务设置读头、空闲和写入超时。把请求取消和总时限传到解析器，限制解压后响应体大小和重定向次数。用慢响应、超大响应及客户端断开验证失败路径。两个 Basic Auth 变量均为空时保留公开模式，仅设置一个变量时启动报错。对外响应避免回显上游 URL 中的凭据和签名。清除代码中的硬编码会话；若凭据仍有效，由所有者撤销并轮换。

4. **安全发布 CLI 下载。** 校验媒体 URL 及跳转目标的协议和地址。使用媒体域名策略，允许必要的 CDN 主机，继续禁止访问特殊用途 IP。只使用受控扩展名，在输出目录写临时文件，下载成功后以具备原子防覆盖语义的文件操作发布。遇到重名返回冲突。用已有同名文件、上游 404、中途断流和并发下载验证旧文件内容保持完整，且失败时没有遗留半成品。

   媒体请求只允许访问同一解析结果中已有媒体地址的可注册域名。这个范围允许同一 CDN 域内切换主机，并隔离公共后缀下的不同租户。最终文件通过同目录硬链接发布，目标文件系统不支持硬链接时返回错误。

5. **升级工具链及依赖。** 用 Go `1.26.10` 重建，统一开发和发布构建版本。将 `golang.org/x/net` 升至至少 `v0.62.0`，按扫描结果更新相关间接依赖并运行平台解析回归。对源码与 Linux 发布二进制重新运行 `govulncheck`，核对公告的具体触发条件。CI 和发布配置在实施这一阶段时单独变更。

6. **启用提交阻断。** Gitleaks 提交时检查暂存区并脱敏。gosec 和 govulncheck 先通过 pre-commit 的 `manual` 阶段运行。修复存量后，确保两项扫描对修复基线成功退出，再切换到 `pre-commit` 阶段。保留工具原有的失败退出码，逐条核实剩余告警。
